# Журнал прогонов

Каждый файл `run_queue*.ps1` — это очередь шагов, которая была реально запущена, с шапкой,
где написано, **что именно она проверяет и почему возник вопрос**. Вместе они образуют
фактическую историю решений проекта: что попробовали, что сломалось, что из этого отозвали.

Логи каждого шага лежат в `../logs/`, имя файла равно имени шага. Сводка по времени и
результату — `../logs/queue_status.txt`.

Скрипты написаны под PowerShell, потому что машина разработки — Windows. К поставке они
отношения не имеют: и конкурсный прогон, и сервис запускаются одной docker-командой на
любой системе. Сюда стоит заглядывать, если нужно понять, откуда взялось конкретное число.

| очередь | что проверяла |
|---|---|
| `run_queue.ps1` | первая ночная очередь: бейзлайны и дообучение |
| `run_queue2.ps1` | исправления после первой очереди |
| `run_queue3.ps1` | привести релиз в соответствие с письменными ответами организаторов |
| `run_queue4.ps1` | проверить релизный образ, переснять производительность на свободной машине |
| `run_queue5.ps1` | финальная сборка из усреднённой модели |
| `run_queue6.ps1` | переснять всё по **правилу жюри** (junk-фильтр только по `vid+cam`) |
| `run_queue7.ps1` | полностью проаудированный релиз по запросу напарника |
| `run_queue8.ps1` | контрольный эксперимент напарника на его протоколе |
| `run_queue9.ps1` | закрыть замечания архитектурного разбора |
| `run_queue10.ps1` | три дефекта уровня P0 из внешнего аудита, пересдача |
| `run_queue11.ps1` | вопрос, на котором держится релиз: суп против одиночных сидов |
| `run_queue12.ps1` | вмерженный патч напарника; **сборка образа упала, и часть «зелёных» шагов ничего не проверила** |
| `run_queue13.ps1` | разбор того, что очередь 12 сделала неправильно; попытка пересобрать образ |
| `run_queue14.ps1` | продукт целиком: обе сборки чинятся, все доказательства сняты заново |
| `run_queue15.ps1` | финальный прогон на замороженном рецепте; harness научился ловить шаг, который молча ничего не сделал |
| `run_queue16.ps1` | новые параметры ре-ранжирования 3/2/0.2, пересборка и пересъём всего |

Две записи здесь важнее остальных, потому что они про ошибки, а не про успехи.

**Очередь 12** собрала образ с ошибкой, но продолжила выполняться: все последующие
docker-шаги отработали на СТАРОМ образе и отчитались успехом. Зелёный отчёт при этом ничего
не доказывал. Разбор — в шапке очереди 13.

**Первая версия очереди 15** прошла целиком за три секунды и отчиталась успехом, не запустив
ни одной команды: у `Tee-Object` в Windows PowerShell 5.1 нет параметра `-Encoding`, конвейер
падал на разборе параметров, а `$LASTEXITCODE` оставался нулём с предыдущего шага. После
этого шаг считается провалившимся не только по коду возврата, но и если он вообще ничего не
записал в лог. Итог очереди печатает список провалившихся шагов поимённо.
