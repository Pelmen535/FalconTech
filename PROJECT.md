# Цифровой отпечаток автомобиля (безномерная идентификация)

Версия документа: 0.2 · Последнее обновление: 2026-09-13

---

## 1. ЧТО СТРОИМ

Сервис, который по кадру с городской камеры формирует устойчивый визуальный
признак автомобиля, не зависящий от госномера, и находит кандидатов на
сопоставление среди ранее зафиксированных событий. Если для части событий
номер был известен, сервис связывает безномерное наблюдение с номером.

**Ключевое отличие от обычного vehicle re-ID:** система измеряет, сколько
информации она реально извлекла, и отказывается называть одного кандидата,
когда данных мало. Выход — ранжированный список с калиброванной уверенностью
и объяснением, а не вердикт.

### Чего НЕ строим

- Не строим распознавание номеров как продукт. OCR используется только как
  источник разметки и якорей.
- Не обучаем ReID-модель с нуля. Только дообучение готовых весов.
- Не делаем систему, выдающую бинарный ответ «это тот автомобиль».
- Не делаем production-деплой, кластеризацию, масштабирование. Прототип.

## 2. КОНТРАКТЫ

**Это закон. Меняется только по явному согласию обоих разработчиков,
с записью в журнал решений.**

Машиночитаемая версия: `contracts/schema.py`. При расхождении между
этим разделом и `schema.py` — истина в `schema.py`.

### Сущности

| Сущность | Назначение |
|---|---|
| `Event` | одно наблюдение автомобиля одной камерой в один момент |
| `Fingerprint` | признаковое описание одного `Event` |
| `VehicleProfile` | накопленный профиль одной машины (объединение событий) |
| `Candidate` | один кандидат в выдаче поиска |
| `SearchResult` | ответ поиска: список кандидатов + диагностика |

### Сквозные соглашения

- Все временные метки — **UTC, tz-aware**. Наивных `datetime` в системе нет.
- Все пути к файлам — **относительные от `DATA_ROOT`**, POSIX-разделители.
- `bbox` — `(x1, y1, x2, y2)`, целые пиксели **в координатах полного кадра**,
  не кропа. Включая левый-верхний, исключая правый-нижний.
- Отсутствующее значение — всегда `None`, никогда пустая строка и не `-1`.
- Все эмбеддинги — `float32`, L2-нормированные, размерность в `EMBED_DIM`.
- Идентификаторы — строки `uuid4()` в hex-виде без дефисов.

### Формат хранения

- События — **JSONL**, одна строка на событие, файл `events/<camera_id>.jsonl`.
- Эмбеддинги — **`.npy`** матрица `(N, EMBED_DIM)` + параллельный
  `ids.json` со списком `event_id` в том же порядке.
- Метрики экспериментов — **CSV**, `docs/metrics.md` содержит сводку.

## 4. СОСТОЯНИЕ

Обновляется в конце каждой сессии. Истина здесь — код, не документ:
если написано «работает», а не работает — чиним документ.

### Работает

- Воспроизводимый smoke baseline в `src/vehicle_reid/`: генерация
  синтетического набора, аудит split, маскирование области номера,
  ColorGrid-эмбеддинг, cross-camera retrieval, Recall@1/5 и mAP.
- Локальный ONNX-адаптер с явной спецификацией препроцессинга.
- CLI-команды `make-demo`, `audit`, `evaluate`, `query` и единый PowerShell-runner.
- Пять тестов контрактов smoke harness и сквозного запуска проходят локально.

### В работе

- Адаптер smoke harness с CSV-манифеста оценки на канонические `Event` JSONL
  и `Fingerprint` из `contracts/schema.py`.
- Интеграция официального датасета и замеры по гейтам дня 2.

### Сломано / известные проблемы

- Текущий ColorGrid baseline проверен только на синтетических изображениях;
  его метрики не характеризуют качество конкурсной модели.
- Smoke harness пока выдаёт cosine similarity, а не калиброванную вероятность
  `Candidate.score`, и не реализует биты, evidence и k-анонимность.

### Замеры по гейтам (заполнить в день 2)

| Гейт | Как меряем | Значение | Вердикт |
|---|---|---|---|
| Разрешение кропа | медиана и p25 длинной стороны | — | нужно ≥200 px |
| Перенос детектора точек | openpifpaf `apollo-24` на 100 кропах, глазами | — | нужна стабильная поза |
| Есть ли приметы | доля машин с видимой приметой из выборки 200 | — | нужно >10% |
| Ночные повторы | есть ли ночные кадры с повторной машиной | — | да/нет |
| Доля читаемых номеров | доля событий, где OCR уверенно читает | — | влияет на идею 2 |

## 5. ЖУРНАЛ РЕШЕНИЙ

Только дописывание. Никогда не переписываем и не удаляем — если решение
отменено, добавляем новую запись с отменой. Формат:
**решили / почему / что отвергли и почему**.

Полная версия — `docs/decisions.md`. Здесь — только действующие решения.

### D-001. Берём в ядро четыре идеи

**Решили:** биты информации (ёмкость отпечатка), граф номеров как источник
обучающих пар, исключение вместо поиска похожих, k-анонимность по построению.

**Почему:** дёшевы, связны между собой (граф даёт обучение, биты дают меру,
исключение даёт объяснение, k-анонимность даёт политику) и закрывают главные
вопросы судей.

**Отвергли:** обучение ReID с нуля — за 15 дней гарантированный провал.

### D-002. Источник меток абстрагирован

**Решили:** единый интерфейс `plate_of(event) -> str | None` с двумя
реализациями: реальный OCR и симуляция (ground-truth ID в роли номера,
выдаётся для X% событий, с шумом распознавания O/0, 8/B, обрезка).

**Почему:** на момент старта неизвестно, дадут ли организаторы данные.
Архитектура не должна этого ждать.

**Бонус:** симуляция позволяет построить кривую «качество vs доля событий
с читаемым номером» от 5% до 100% — это сильнее одной точки на реальных
данных. Подаём как методологический выбор, не как замену.

### D-003. UV-развёртка условна и строится уровнями

**Решили:** L0 (корзины ракурса + сегментация частей) делаем всегда.
L1 (варп в канонический 2D-шаблон внутри корзины) — почти всегда.
L2 (настоящая UV на меше) — только если гейты дня 2 зелёные.

**Почему:** высокая дисперсия результата. Каждый уровень самостоятельно
защитим, поэтому остановка на L1 не потеря.

**Жёсткое правило:** если к концу дня 9 L2 не работает end-to-end — убиваем
и идём с L1. Решение по календарю, не по ощущению.

### D-004. Развёртка всегда частичная

**Решили:** каждое наблюдение даёт тройку `(T, M, Q)` — частичный атлас,
маску валидности, карту качества. Сравнение только по `M_A · M_B`.
Профиль машины — накопление по трекам и по графу номеров:
`T = Σ(T_i·Q_i)/Σ(Q_i)`, `M = ⋃ M_i`.

**Почему:** с одного ракурса видно меньше половины поверхности. Площадь
пересечения масок — это и есть верхняя граница информации, которую
сравнение может дать. Связывает UV с идеей битов напрямую.

### D-005. Зеркальная симметрия — только гипотеза

**Решили:** зеркалирование бортов разрешено для повышения кандидата
в ранжировании. **Запрещено** для подтверждения совпадения и для исключения.

**Почему:** вмятина на левой двери не повторяется на правой. Симметрия верна
для заводского слоя и ломается ровно на отличительных признаках.

### D-006. Гейт качества позы

**Решили:** растеризуем меш с подогнанной позой, считаем IoU с сегментацией
силуэта. IoU < 0.8 — наблюдение выбрасывается целиком.

**Почему:** ошибка позы тихая — атлас выглядит правдоподобно, но признаки
уезжают. Пять хороших кадров лучше пятидесяти кривых: кривые портят
накопленный атлас.

### D-007. Репозиторий публичный, данные — вне git

**Решили:** код и документация в публичном GitHub; датасеты, чекпоинты,
видео — на облачном диске, ссылки и контрольные суммы в `docs/data.md`.

**Почему:** публичный репозиторий снимает возню с авторизацией у второго
разработчика. Тяжёлые бинарники в git не помещаются и не нужны.

## 6. НЕ ДЕЛАТЬ

Явные запреты. Если ИИ предлагает что-то из этого списка — отказываемся
и ссылаемся на пункт.

- **Не обучать ReID с нуля.** Только дообучение готовых весов.
- **Не ставить PyTorch3D / nvdiffrast.** Они компилируют CUDA-расширения,
  под sm_120 (Blackwell) готовых сборок нет. Для UV-проекции дифференцируемый
  рендер не нужен: растеризация + барицентрические координаты + z-буфер
  пишутся руками или берутся через `moderngl`/`pyrender` без CUDA.
- **Не класть в git** данные, чекпоинты, `runs/`, видео, кропы.
- **Не менять контракты в одиночку.** Только по согласию, с записью в журнал.
- **Не выдавать один ответ.** Выход системы — всегда ранжированный список
  с уверенностью. Ни в одном месте кода не должно быть «это тот автомобиль».
- **Не зеркалить признаки для исключения** (см. D-005).
- **Не мерить качество сплитом по кадрам.** Только сплит по идентичностям,
  иначе метрика завышена и это вскроется на защите.
- **Не выносить на слайд код, который не можешь объяснить построчно.**
