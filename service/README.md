# Бэкенд к ядру 19b

Сервис использует **исходное ядро Николая** через отдельный адаптер. Веса, recipe, обучение и файлы vreid не изменяются.

## Запуск в этом проекте

```powershell
.\scripts\start_backend.ps1
```

Открыть http://127.0.0.1:8765. По умолчанию CPU и полученный исходный 19b. Первая операция извлечения признаков загружает модель. Галерея сохраняется в var/backend/gallery.sqlite3, поэтому перезапуск не требует пересчёта векторов.

В другом каталоге или в среде Николая сначала установить сервисные зависимости **в существующую среду ядра**, затем указать путь к распакованному ядру:

```text
python -m pip install -r src/service/requirements.txt
python scripts/run_backend.py --core-dir /path/to/vreid_2026-09-19b --device cpu
```

Для доступной видеокарты можно указать --device cuda. Копировать или обновлять веса для работы сервиса не требуется. --release-dir выбирает отдельный release; --data-dir задаёт постоянное хранилище. Существующая галерея привязана к SHA модели, recipe и размерности: при их замене нужен новый каталог данных.

## Что работает

- Загрузка одного наблюдения: фото, bbox xywh, необязательный ID.
- Импорт ZIP: test_gallery.csv с image_id,x,y,w,h и images/; имена изображений соответствуют image_id. Весь пакет записывается атомарно после извлечения векторов.
- Поиск по новому фото: исходная предобработка и модель, полная галерея, один query, исходный rerank и порог.
- Десять кандидатов всегда возвращаются при достаточной галерее; accepted=false и candidate=null означают отказ.
- Просмотр исходных изображений и миниатюр размеченных автомобилей, список и удаление наблюдений.
- SQLite хранит изображения, bbox и векторы. Постоянные данные переживают перезапуск.
- Локальная страница работает без CDN; описание API доступно в /openapi.json.

Это отдельный HTTP-контракт: 1536D текущего ядра, xywh, сырой cosine. Он не меняет contracts/schema.py и не преобразует cosine в вероятность.

## HTTP

| Метод | Путь | Вход / результат |
|---|---|---|
| GET | /health | Состояние процесса, число записей, загрузка модели |
| GET | /v1/model | Хэши, размерность, порог, устройство |
| GET | /v1/gallery?offset=0&limit=100 | Список наблюдений |
| POST | /v1/gallery/items | multipart: image, bbox='[x,y,w,h]', image_id необязательно |
| POST | /v1/gallery/import | multipart: archive — ZIP |
| GET | /v1/gallery/items/{id}/image | Исходное изображение; ?crop=true — миниатюра автомобиля |
| DELETE | /v1/gallery/items/{id} | Удаление записи |
| POST | /v1/search | multipart: image, bbox, query_id необязательно |

Передавать query_id, если исходный кадр уже находится в галерее: он будет исключён из выдачи. Для поиска нужны десять допустимых записей после исключения. Предоставленный bbox должен находиться внутри кадра.

Пример:

```text
curl -F "image=@query.jpg" -F "bbox=[100,100,400,200]" http://127.0.0.1:8765/v1/search
```

Ответ включает ranking, accepted, candidate, threshold, confidence_scale=raw_cosine, gallery_count, хэши модели/recipe и время запроса. Порядок ranking может отличаться от сортировки по cosine после rerank.

## Границы первой версии

Один процесс и одна операция модели одновременно; конкурирующий запрос получает 503 с Retry-After. До 1500 изображений в галерее, 20 МиБ на кадр и 128 МиБ на ZIP. Импорт на CPU синхронный и может занять время. Галерея общая для этого экземпляра сервиса.

По умолчанию сервер слушает только localhost. Для адреса в локальной сети задать VREID_API_KEY и передавать X-API-Key. Пользовательские роли, распределённая очередь и внешняя БД не входят в эту версию.

## Проверка

```text
python -m pytest tests/backend -q
```

Для pytest требуется PYTHONPATH=src. Тесты HTTP используют явно тестовый encoder; сквозной запуск настоящей модели описан в outputs/backend_2026-09-20/. Ни smoke, ни HTTP-тесты не являются оценкой accuracy.

Техническая основа: [FastAPI UploadFile](https://fastapi.tiangolo.com/tutorial/request-files/). Публичная спецификация нашего сервиса — его собственный /openapi.json.
