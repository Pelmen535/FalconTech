# Архитектура v2.0

Точки входа: `scripts/october_entrypoint.py` для Docker, `scripts/predict_october.py` для пакетного прогона, `scripts/run_service.py --backend october` для HTTP. Все используют `release_current/runtime-manifest.json` и `service/october_worker.py`.

1. Nginx отдаёт тонкий клиент и проксирует API. Web подключён к локально публикуемой frontend-сети и внутренней сети. API и PostgreSQL доступны только во внутренней сети без внешнего egress. Статические Swagger-ресурсы входят в проект.
2. FastAPI проверяет изображение, рамки и ID. Слой хранения сохраняет наблюдение, байты изображения, bbox, timestamp, content revision и ссылку `feature_ref` на сохранённые признаки.
3. OctoberAdapter управляет deadline-bound RPC. JSON-ответы отделены от native stdout TensorRT на уровне файловых дескрипторов. Логирование идёт в stderr с request/rpc ID. Сбой или зависание своего воркера приводит к ограниченному по времени отказу запроса и последующему восстановлению; чужие процессы не останавливаются.
4. NativeFeatures декодирует JPEG и вырезает bbox; DINOv3 384×384 и CNN 256×256 дают по 2048 сырых компонент. Linux GPU использует два SM86 TensorRT engine; CPU — отдельный FP32 backend и отдельный namespace признаков.
5. RawReferenceStore идентифицирует обе сырые ветви, их канонические dtype/shape, extractor namespace и версию схемы. Query остаётся в ограниченном in-memory кеше; его признаки не добавляются в статическую галерею. Перезапуск не требует прогонять энкодер ради восстановления сохранённой gallery-ссылки.
6. OctoberMath строит фиксированные проекции, gallery-centering/whitening и графы. Каждое решение использует одну query и gallery, не остальные query. Признаки сходства и графового окружения поступают в фиксированную цепочку оценки уверенности и отказа.
7. Exact и ANN используют одну математику. ANN ограничивает query-insertion этап, затем консервативно расширяет shortlist, когда пропущенный кандидат ещё может войти в top‑10. Поэтому ANN не гарантирует ускорение и может завершиться полным поиском.
8. `embeddings.npy` содержит L2-нормированный CNN-признак размерности 512 после gallery adaptation. Формат: float32, сначала query, затем gallery в порядке входных CSV.

Хранилище выбирается по DSN: PostgreSQL + pgvector в Compose, SQLite для локального режима. Ранжирование и проверка полноты ANN выполняются внутри backend. Схема хранения — `raw-pair-le-v2`.

Резервная копия связывает SQL-снимок, изображения, рамки, timestamps, raw-features и runtime manifest. Старые 1536D-вектора не пересчитываются алгебраически в новые: миграция заново извлекает признаки из исходных изображений в отдельную новую галерею. Исходная версия и её БД сохраняются для отката. [Операции хранения](../service/README.md).

Runtime контролирует свободную память, место на диске, сроки выполнения и лимиты очередей. Проверенный диапазон и ограничения — [A5000-отчёт](V2_A5000_REPORT_RU.md). Происхождение весов и источники — [SOURCES.md](../SOURCES.md).
