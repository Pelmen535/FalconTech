# HTTP API v2.0

Базовый адрес: `http://localhost:8080`. Актуальная схема — `/openapi.json`, интерактивная документация — `/docs`; Swagger-ресурсы доступны офлайн. Запуск и настройка хранилища: [README](../README.md), [операции сервиса](../service/README.md).

Если задан `VREID_API_KEY`, к запросам `/v1/*` добавляется заголовок `X-API-Key`. Ответы содержат `X-Request-ID`, связанный с журналом операций.

## Форматы и уверенность

- Рамка `bbox` — JSON-массив `[x,y,w,h]` в пикселях исходного кадра, целиком внутри изображения.
- `confidence` — итоговая шкала принятия `calibrated_acceptance_score`. Это не исходный cosine и не вероятность правильности.
- Порог текущего профиля — **0.7988346717209206**. Актуальное значение и отпечатки доступны через `/v1/model`.
- Отказ: `accepted: false`, `candidate: null`; список `ranking` остаётся доступен.
- В `ranking` поле `cosine` показывает исходное сходство пары, `ranking_score` — итоговую оценку ранжировщика. Порядок задаётся последней.
- Одновременно выполняется одна операция модели. При занятости возвращаются `503` и `Retry-After`.

## Состояние

| Метод | Путь | Содержимое |
|---|---|---|
| GET | `/health` | Состояние, устройство, хранилище и число наблюдений |
| GET | `/v1/model` | Модель, порог, шкала уверенности, форматы признаков, функции и runtime identity |
| GET | `/v1/index/stats` | Состояние exact/ANN и параметры индекса |

`model_sha256` идентифицирует веса, `recipe_sha256` — конфигурацию обработки и принятия, `embedding_sha256` — пространство извлечения признаков. CPU и TensorRT используют отдельные пространства. При несовместимом пространстве галерею нужно мигрировать, повторно извлекая признаки из исходных изображений.

## Галерея

| Метод | Путь | Вход |
|---|---|---|
| GET | `/v1/gallery?offset=&limit=` | Постраничный список наблюдений |
| POST | `/v1/gallery/items` | multipart: `image`, `bbox`, необязательный `image_id` |
| POST | `/v1/gallery/import` | multipart: `archive` — ZIP с `test_gallery.csv` и `images/` |
| GET | `/v1/gallery/items/{image_id}/image` | Исходное изображение; `?crop=true` — миниатюра |
| DELETE | `/v1/gallery/items/{image_id}` | Удаление наблюдения |

CSV импорта содержит `image_id,x,y,w,h`. Импорт атомарен; конфликт существующего ID даёт `409` без перезаписи галереи. Изображения, рамки и raw-cache входят в резервную копию вместе с SQL-снимком.

Необязательные демонстрационные методы включаются через `VREID_DEMO_UI=1`: `/v1/demo`, `/v1/demo/query.jpg`, `/v1/demo/gallery`. Требуется отдельно установленный демонстрационный набор; по умолчанию кнопки выключены.

## Поиск

```bash
curl -F "image=@query.jpg" -F "bbox=[1202,270,588,474]" \
  http://localhost:8080/v1/search?mode=exact
```

Дополнительное multipart-поле `query_id` исключает наблюдения того же кадра по префиксу ID до `#`. Для поиска нужны минимум десять допустимых наблюдений после исключений. Текущий backend явно отклоняет неподдерживаемые sparse multibox-галереи.

`mode=exact` использует всю галерею. `mode=ann` формирует HNSW shortlist перед query-insertion reciprocity, сохраняя полную статическую gallery adaptation и графовый контекст. Затем консервативная проверка дополняет shortlist вплоть до полного поиска. Ускорение не гарантировано. Фактический режим и пояснения возвращаются в `search_mode` и `notes`.

Основные поля ответа:

| Поле | Значение |
|---|---|
| `accepted`, `candidate` | Решение и выбранное наблюдение либо `null` |
| `confidence`, `threshold`, `confidence_scale` | Итоговый score, порог и шкала |
| `ranking` | До десяти кандидатов: ID, rank, cosine, ranking_score и URL изображений |
| `gallery_count`, `search_mode`, `shortlist_seconds`, `notes` | Состав и режим поиска |
| `model_sha256`, `recipe_sha256` | Отпечатки действующей модели и конфигурации |
| `seconds` | Время обработки запроса |

## Объяснение пары

```bash
curl -F "image=@query.jpg" -F "bbox=[1202,270,588,474]" \
  -F "gallery_id=selected-id" http://localhost:8080/v1/explain?regions=3
```

Метод последовательно восстанавливает области изображения при фиксированной галерее и оценивает изменение среднего cosine DINOv3/CNN после gallery adaptation. Ответ содержит PNG-карты обеих сторон пары, метод, области вклада и ошибку реконструкции. Если исходное сходство или его реконструкция не воспроизводятся с допуском 1e-6, карта не выдаётся.

Объяснение относится к сходству пары. Оно не раскладывает нелинейный реранкинг и решение об отказе; это не Grad-CAM и не Shapley attribution.

## Коды ответов

| Код | Причина |
|---|---|
| 200 / 201 / 204 | Успех; 204 — удаление |
| 400 | Некорректный заголовок запроса |
| 401 | Неверный или отсутствующий API key при включённой аутентификации |
| 404 | Наблюдение/файл не найдены, демонстрационный набор недоступен |
| 409 | Дубликат ID, лимит или слишком малая галерея |
| 413 | Превышен лимит размера запроса/архива |
| 422 | Некорректное изображение, bbox, архив, режим или неподдерживаемая галерея |
| 500 | Ошибка выполнения; request ID позволяет найти запись в журнале |
| 501 | Backend не поддерживает объяснение |
| 503 | Модель занята либо недостаточно ресурсов |

Для пакетной обработки без HTTP используйте [CLI v2.0](../README.md#13-пакетный-прогон). Экспорт включает `submission.csv`, `candidates.csv`, `embeddings.npy` и `run_info.json`.
