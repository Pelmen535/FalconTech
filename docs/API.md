# HTTP API

Машинное описание — `/openapi.json`, интерактивное — `/docs` (Swagger UI, работает без
интернета). Этот файл объясняет то, чего в схеме не видно: что означают числа и какие
решения сервис принимает за вас, а какие нет.

Базовый адрес прототипа: `http://localhost:8080`. Все пути `/v1/*` требуют заголовка
`X-API-Key`, если на сервере задана переменная `VREID_API_KEY`; по умолчанию ключа нет,
потому что наружу публикуется только веб-слой.

## Соглашения

* **Рамка — `xywh`** в пикселях исходного кадра: левый верхний угол, ширина, высота.
  Рамка обязана лежать внутри кадра.
* **Уверенность — сырой косинус** выбранного кандидата, число в `[-1, 1]`. Это не
  вероятность и не калиброванная шкала. Монотонность — единственное, на что можно
  опираться.
* **Отказ** — это `accepted: false` и `candidate: null`. Ранжирование при этом всё равно
  возвращается: оператору полезно посмотреть, но в конкурсный `candidates.csv` такой запрос
  не попал бы ни одной строкой.
* **Порядок кандидатов** может отличаться от порядка косинуса: ранжирование выдаётся после
  ре-ранжирования k-reciprocal (3/2, λ=0.2), а `cosine` в каждой карточке — исходная мера сходства.
* **Одна операция модели за раз.** Конкурирующий запрос получает `503` и заголовок
  `Retry-After`, а не молча встаёт в очередь неизвестной длины.

## Состояние

| метод | путь | что делает |
|---|---|---|
| `GET` | `/health` | статус, число наблюдений, устройство, тип хранилища, отпечатки модели и рецепта |
| `GET` | `/v1/model` | порог, размерность, вид уверенности, режим ре-ранжирования |
| `GET` | `/v1/index/stats` | текущий режим поиска, параметры ANN и измеренные цифры до 10⁶ |

В `/health` два разных отпечатка, и путать их не надо:

* `recipe_sha256` — хэш файла `recipe.json` целиком, провенанс;
* `embedding_sha256` — отпечаток **извлечения**: веса плюс те поля рецепта, от которых
  зависит сам вектор (`crop_pad`, `fast_decode`, `tta_flip`). Галерея привязана именно
  к нему. Правка порога отказа не обесценивает уже посчитанные векторы, а смена весов или
  параметров кропа — обесценивает, и тогда хранилище отвергается с внятным сообщением.

## Галерея

| метод | путь | вход |
|---|---|---|
| `GET` | `/v1/gallery?offset=&limit=` | постраничный список наблюдений |
| `POST` | `/v1/gallery/items` | multipart: `image`, `bbox='[x,y,w,h]'`, необязательный `image_id` |
| `POST` | `/v1/gallery/import` | multipart: `archive` — ZIP с `test_gallery.csv` и `images/` |
| `GET` | `/v1/gallery/items/{id}/image` | исходный кадр; `?crop=true` — миниатюра автомобиля |
| `DELETE` | `/v1/gallery/items/{id}` | удалить наблюдение |
| `GET` | `/v1/demo` | есть ли в сборке демонстрационный набор |
| `POST` | `/v1/demo/gallery` | загрузить демонстрационные 20 кадров (только в пустую галерею) |

Импорт атомарен: либо записываются все наблюдения архива, либо ни одного. Совпадение
`image_id` с уже существующим отменяет импорт целиком — это `409`, а не тихая перезапись.

## Поиск

```
POST /v1/search?mode=exact|ann
multipart: image=<файл>, bbox='[1202,270,588,474]', query_id=<необязательно>
```

`query_id` указывается, если этот же кадр уже лежит в галерее: тогда он исключается из
выдачи. После исключения должно остаться не меньше десяти наблюдений.

`mode=exact` — полный перебор, ответ совпадает с конкурсным CLI. `mode=ann` — шортлист
HNSW, затем тот же точный косинус и то же ре-ранжирование внутри шортлиста. На галерее
меньше 256 записей ANN не включается, и сервис пишет об этом в поле `notes`, а не делает
вид, что применил.

Ответ:

```json
{
  "ranking": [{"image_id": "...", "rank": 1, "cosine": 0.8387,
               "image_url": "...", "thumbnail_url": "..."}],
  "accepted": true,
  "candidate": {"image_id": "...", "rank": 1, "cosine": 0.8387},
  "threshold": 0.55,
  "confidence_scale": "raw_cosine",
  "search_mode": "exact",
  "shortlist_seconds": null,
  "gallery_count": 20,
  "notes": [],
  "model_sha256": "...", "recipe_sha256": "...",
  "seconds": 0.31
}
```

```bash
curl -F "image=@query.jpg" -F "bbox=[1202,270,588,474]" \
     http://localhost:8080/v1/search
```

## Объяснение

```
POST /v1/explain?regions=3
multipart: image=<файл>, bbox='[x,y,w,h]', gallery_id=<id кандидата>
```

Возвращает по карте вклада на каждую сторону пары: PNG в base64 плюс числа. Это **не**
Grad-CAM: косинус раскладывается по участкам кадра точно, и поле `reconstruction_error`
показывает, насколько сумма частей отличается от целого (на релизной модели — ноль).

```json
{
  "cosine": 0.8387, "threshold": 0.55,
  "method": "exact additive decomposition of the cosine over patch tokens",
  "sides": {
    "query":     {"grid": [24, 24], "patch_sum": 0.3926, "constant": 0.4461,
                  "reconstruction_error": 0.0, "top_regions": [...],
                  "heatmap_png_base64": "..."},
    "candidate": {"...": "..."}
  },
  "seconds": 0.9
}
```

Зелёный на карте — участок добавил сходства больше типичного, красный — меньше, серый —
как все. Карта центрирована по среднему: у похожей пары почти все участки вносят
положительный вклад, и некентрированная картинка «всё зелёное» не говорила бы ничего.

## Коды ответов

| код | когда |
|---|---|
| `200` / `201` | успех |
| `401` | задан `VREID_API_KEY`, а заголовок не совпал |
| `404` | нет такого наблюдения или файла |
| `409` | дубликат `image_id`, переполнение галереи, попытка залить демо в непустую галерею, меньше десяти доступных наблюдений для поиска |
| `413` | тело запроса больше лимита |
| `422` | некорректные рамка, изображение, архив или значение `mode` |
| `501` | загруженное ядро не умеет объяснять (например, подменено на тестовое) |
| `503` | модель занята другим запросом, см. `Retry-After` |

## Встраивание без HTTP

Если сервис не нужен, ядро вызывается напрямую тремя строками:

```python
from vreid.models import get_backbone
from vreid.extract import crop_bbox

backbone = get_backbone("ft:release/model.pt")      # один раз при старте, ~3 с
crop = crop_bbox(pil_image, (x, y, w, h), pad=0.05)
vector = backbone.embed([crop])[0]                   # np.float32[1536], уже L2-нормирован
```

Порог берётся из `release/recipe.json` и применяется к косинусу с лучшим кандидатом.
Ниже порога система обязана вернуть пустой ответ, а не «лучшее из плохого».
